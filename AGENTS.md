# AGENTS.md

Chrome Manifest V3 extension. No build step, no package.json, no test runner, no lint.
All source is plain JS/HTML/CSS loaded directly by the browser.

## Load / run
- Load unpacked: `chrome://extensions` → Developer mode → "Load unpacked" → repo root.
- Requires Chrome >= 116 (manifest `minimum_chrome_version`); the `sidePanel` API is the reason.
- After any edit: reload the extension; also reload the target tab for injected (`content.js`) changes.
- Render sanity check (no browser needed): `node -e "const m=require('./vendor/marked.min.js');m.setOptions({gfm:true,breaks:true});console.log(m.parse('# hi\n\n**x**'))"`

## Layout — own code in `js/`, styles in `css/`, third-party in `vendor/`
- Root: `manifest.json`, `sidepanel.html`, `popup.html`, `options.html`, `icons/`.
- `js/`: `background.js` (service worker), `content.js` (injected popup), `overlay.js` (fullscreen overlay host), `sidepanel.js`, `popup.js`, `options.js`, `setupMarked.js`, `themes.js`, `storage.js`.
- `css/`: `styles.css`, `highlight.css`, `highlight-dark.css`.
- `vendor/`: all third-party + generated libs (marked, highlight, turndown, dompurify, plugins, `emoji-map.js`). Do not edit.
- Paths are relative (`js/…`, `css/…`, `vendor/…`) in `manifest.json`, `js/background.js` `INJECT_FILES`, `<script>`/`<link>` tags, and `chrome.runtime.getURL('css/highlight*.css')`. `manifest.json` stays at root (unpacked load dir).

## Architecture — three render surfaces + PR fetch, one lib stack
- `background.js` (service worker) is the orchestrator: three context menus (`Preview as Markdown`, `Convert HTML to Markdown`, and `Preview PR as Markdown (raw)`, `documentUrlPatterns`-restricted to GitHub/Bitbucket PR pages), reads `mdPreviewConfig.mode` from `chrome.storage.local`, then branches:
  - `mode === 'overlay'`: stash the live selection in `chrome.storage.session` (`pendingMarkdown` / `pendingHtml`) and inject `js/overlay.js` via `chrome.scripting` (`activeTab`). The host iframes `sidepanel.html?embed=1` fullscreen; the embedded page reads the stash on boot or via `storage.onChanged`.
  - `mode === 'sidebar'`: `chrome.sidePanel.open` (must run while user gesture is active), stash selection in `chrome.storage.session` (`pendingMarkdown` / `pendingHtml`). Panel picks it up via `storage.onChanged` or on first load.
  - else (popup): inject `INJECT_FILES` (libs then `content.js`), grab live selection + rect, `tabs.sendMessage` (`renderMarkdown` / `convertHtmlToMarkdown`). On restricted pages (`chrome://`, etc.) falls back to side panel / full tab.
- PR preview (`MENU_PR_MD`): `parsePrUrl()` parses `…/pull/N` / `…/pull-requests/N` URLs (owner must be exactly one segment), `fetchPrMarkdown()` calls the host's REST API (`api.github.com` / `api.bitbucket.org` — the manifest's only `host_permissions`) and composes title + meta + body + comments into one markdown doc. Optional tokens from `chrome.storage.local` `mdApiTokens` (`{ githubToken, bbUsername, bbAppPassword }`, set on the options page) authenticate private repos; GitHub uses `Bearer`, Bitbucket uses Basic (username + app password). Fetch errors render as markdown (`# Could not fetch Pull Request …`) instead of dying silently. `routePrMarkdown()` then reuses the three mode branches; `sidePanel.open` still happens synchronously in the gesture, before the fetch, when mode is `sidebar`.
- `content.js` — floating popup injected into the page. Inline styles + `--md-*` vars only; never uses `styles.css`. Draggable/resizable, Esc-to-close, re-injection guard (existing box → re-bind listener, re-position).
- `overlay.js` — fullscreen host shell only: fixed root + `sidepanel.html?embed=1` iframe (max z-index), idempotent re-injection guard, Esc fallback, and a `postMessage` close channel (`{ source:'marklens', action:'close-overlay' }`, verified against `frame.contentWindow`). It loads no vendored libs — the iframe loads them itself.
- `sidepanel.html` / `sidepanel.js` — extension-page editor (split/edit/preview, MD↔HTML toggle). Styled by `styles.css` + `--bg/--surface/...` vars. Also runs embedded as the overlay (`?embed=1`): `body.embed` reveals `#overlay-close-btn`, Esc posts the close message, and pending selections land in split view instead of preview-only.
- `popup.js`, `options.js` — thin storage readers/writers, no rendering. `options.html` (`open_in_tab`) holds default mode/theme/font/size + About.

## File roles
- `manifest.json` — entrypoint: service worker, `popup.html`, `options.html`, `sidepanel.html`, icons, `web_accessible_resources` (includes `sidepanel.html` for the overlay iframe).
- `overlay.js` — injected fullscreen overlay host (see Architecture); only `chrome.runtime.getURL('sidepanel.html?embed=1')` + Esc/close plumbing.
- `setupMarked.js` — configures `globalThis.marked` once (GFM, breaks, footnote/deflist/extras/emoji/highlight). Exposes `setupMarked()`; safe to call repeatedly.
- `themes.js` — single source of truth: `MD_THEMES` (22 popup `--md-*` themes) and `MD_SIDEPANEL_THEMES` (22 `--bg/--surface/...` themes). `content.js` / `sidepanel.js` only reference these globals.
- `storage.js` — shared bridge: `mdStorage.load(defaults, cb)` / `mdStorage.save(config)` for key `mdPreviewConfig`.
- Vendored, do not edit: `marked.min.js` (v15, `globalThis.marked`), `marked-footnote.umd.js`, `marked-deflist.umd.js` (hand-written definition lists), `marked-emoji.umd.js` + `emoji-map.js` (1913 gemoji codes → `EMOJI_SHORTCODES`), `marked-highlight.umd.js`, `marked-extras.umd.js` (heading `{#id}`, `==mark==`, `~sub~`, `^sup^`), `highlight.min.js` (v11, `globalThis.hljs`), `highlight.css` / `highlight-dark.css`, `dompurify.min.js` (v3), `turndown.min.js` + `turndown-plugin-gfm.js` (`globalThis.TurndownService`, HTML→MD).
- `styles.css` — shared by side panel, popup, and options pages only.
- `CHANGELOG.md` — release history ([Keep a Changelog](https://keepachangelog.com/en/1.1.0/) format). When bumping `manifest.json` `version`, add an entry here, mirror it in the README Version section, and rebuild `marklens-<version>.zip` (manifest.json, sidepanel.html, popup.html, options.html, js/, css/, vendor/, icons/).

## Gotchas
- Injection / script order is load order — `js/background.js` `INJECT_FILES` and `<script>` tags in `sidepanel.html` must keep vendored libs before `js/setupMarked.js` / `js/themes.js` → `vendor/dompurify.min.js` → `vendor/codemirror/*` (core, `mode/xml`, `mode/markdown`, placeholder, searchcursor, search, dialog, `keymap/vim`) → `js/storage.js` → `js/content.js`/`js/sidepanel.js`. Do not reorder: renderers call `marked.use(...)` at boot and assume globals exist. Repeat right-clicks skip libs (only `js/content.js` re-injected) — see `libsReady()`.
- Side-panel editor is CodeMirror 5 (`theme: 'marklens'`, styled in `css/styles.css` from theme vars so all 22 themes apply). Never touch `#editor` directly — use `getText()`/`setText()`/`focusEditor()`/`setPlaceholder()` (hidden-textarea fallback when CM fails). `setText()` sets a `silentSet` guard so the synchronous CM `change` event doesn't schedule a second render that would wipe status messages (`From selection`, `Draft restored`). `config.keymap` (`default`/`vim`, side-panel-only pref) is applied via `setKeymap()`; Vim requires `CodeMirror.Vim` (guarded). `initEditor()` runs once inside the boot `loadConfig` callback after `applyConfig()`; pending-selection `setText()` calls before/after init are both safe (`fromTextArea` inherits textarea content).
- Plugin export shapes differ: `markedFootnote` is a bare function (`marked.use(markedFootnote())`); all others are named exports (`marked.use(lib.markedX())`). Emoji needs `EMOJI_SHORTCODES` loaded first.
- Sanitize every `marked.parse` / Turndown result with `DOMPurify.sanitize()` before `innerHTML` (page selections are untrusted XSS surface). Errors surface inline (`<pre style="color:#c00">` + `status` text), never throw.
- *Convert HTML to Markdown* has a source-detection shortcut: if the selection's text scores ≥ 6 on `looksLikeMarkdown()` in `content.js` (fenced code, task lists, and a table-separator row each count strongly), tagged HTML is rendered as-is instead of run through Turndown (which mangles fences/tables from syntax-highlight editors). Don't lower the threshold — plain prose must stay out of the score.
- Storage contract: `chrome.storage.local` `mdPreviewConfig` = `{ mode, theme, fontSize, fontFamily }` (popup adds `width`/`height`); `DEFAULTS` is duplicated in `content.js`, `sidepanel.js`, `options.js`, `popup.js` — keep aligned. Separate key `marklensDraft` = `{ text, inputMode, updatedAt }` holds the autosaved editor draft (side panel only; restored on boot unless a pending selection wins). Separate key `mdApiTokens` = `{ githubToken, bbUsername, bbAppPassword }` holds the optional PR-preview credentials (only read by `background.js`, written only by `options.js`). `chrome.storage.session` `pendingMarkdown` / `pendingHtml` is a one-shot bridge (consumed and deleted on read; `stashForSidePanel()` skips empty values so no orphan entries linger). `sidePanel.open` must be called synchronously in the gesture handler or Chrome rejects it.
- Side-panel extras: export via Blob download (`↓ MD` / `↓ HTML` standalone doc) and `window.print()` + `@media print` CSS for Save-as-PDF (no new permissions); drag-drop `.md/.txt/.html` onto `.editor-pane` (`FileReader`, HTML feeds `inputMode='html'`); proportional scroll sync both directions with re-entrancy guard; Zen mode = `body.zen` hides topbar/toolsbar/statusbar (session-only, `Alt+Z`, `Esc` exits).
- Overlay mode: `js/overlay.js` is a content-script-style host (isolated world) that iframes `sidepanel.html?embed=1`; `sidepanel.html` must stay in `web_accessible_resources` or the frame is blocked. `EMBED` requires a real parent window, so opening `sidepanel.html?embed=1` directly in a tab behaves like the normal editor (no close button). The close channel is a one-way `postMessage` (`{ source:'marklens', action:'close-overlay' }`) verified with `e.source === frame.contentWindow`; Esc inside the iframe never reaches the host, so both sides implement it. In `vim` keymap Esc stays in CodeMirror (leave insert mode) instead of closing the overlay. The overlay shares `marklensDraft` + the IndexedDB document library with the side panel.
- Status-bar actions are `.status-btn` pills (icon + `.sb-label`, grouped by `.status-group` with `.status-divider`s). The Copy button carries an SVG, so its changing label is a span — update it via `setCopyLabel()`, never `copyBtn.textContent`. Panel toggles get `.active` + `aria-pressed` through `setPanelBtnActive()`. `@media (max-width: 1080px)` collapses labels to icons (tooltips/aria-labels carry the names), so any new action needs both a `title` and an `aria-label`.
- Topbar layout is two clusters: `.topbar-left` (wordmark + view tabs) and `.topbar-right` (MD/HTML mode + Zen/settings/close). Put new controls inside a cluster — adding direct children of `.topbar` lets `space-between` scatter them across the window. Below 560px the wordmark, dividers and toolsbar dividers drop out so both bars stay compact.
- The Outline/Theme rails share `.docs-panel`. Outline rows are `.outline-item` with `data-line` + `--indent`; `updateOutline()` rebuilds them and `syncOutlineActive(line)` (from CodeMirror `cursorActivity`) marks the heading at/above the cursor. `#outline-count` shows the heading count. The preview-TOC checkbox is a `.switch-row` switch, not a bare checkbox.
- Custom themes are `.theme-item` cards (`data-theme-id`) whose `.theme-apply` button applies on click; `#themes-count` shows the total. The builder's live `#theme-preview` reads the color inputs; `loadThemePalette()` syncs the form to an applied custom theme when `themeDraftDirty` is false, `applyBasePalette()` reloads Light/Dark colors on Base/Reset, and `checkThemeContrast()` flags body/secondary/accent colors below readable contrast. Keep `THEME_COLOR_KEYS` in sync with the seven builder inputs; each swatch shows its live `#hex` via `.cf-hex` (synced by `syncThemeHexCodes()`), and native select popups/scrollbars follow the theme because `applyTheme()` sets root `color-scheme: dark|light` from the background luminance. `themeDraftDirty` is set on any palette edit and cleared after Save so applying a theme never discards an in-progress draft.
- Filled accent/error surfaces must use `var(--on-accent)` / `var(--on-error)`, not `#fff`. `applyTheme()` computes both via `onAccentColor()` from the theme's accent/error luminance, so light accents get dark text and dark accents get white. `:root` defaults keep unthemed pages (options/popup) readable; the builder's `Aa` chip uses `--tp-on-accent` from the draft accent.
- Destructive actions use `mdConfirm({ title, message, confirmLabel, tone })` (promise, `tone: 'danger' | 'accent' | 'warning'`) instead of `window.confirm`; text-entry dialogs (rename on double-click, snapshot labels) use `mdPrompt({ title, value, placeholder, icon, confirmLabel })` instead of `window.prompt` (resolves the input value on Save, `null` on Cancel/Esc/backdrop). Both resolve only one dialog at a time — opening either closes an open one. Markup is `#confirm-modal` / `#prompt-modal`, styled by `.confirm-*`/`.confirm-input` in `styles.css`. Both focus Cancel by default for danger / the input (pre-selected) for prompt, trap Tab, restore focus, and stop keydown propagation so Esc closes the dialog rather than the overlay. Fallback is native confirm/prompt if a modal is missing.
- Theme `<option>` lists in `sidepanel.html` / `options.html` / `content.js` popup template must match the 22 keys in `themes.js`. Side panel swaps `highlight.css` ↔ `highlight-dark.css` via `<link>` href from `theme.hl`; both files must stay in `web_accessible_resources`. MV3 CSP is `script-src 'self'` — no remote scripts.
- Manifest icons (`icons/icon16/48/128.png`) must exist or Chrome rejects load. Plain ES `var`/`function` style throughout (matches vendored UMD); no modules, no bundler.
